# BGX222 架构审查

审查对象是当前工作区中的 POC，不是产品文档里的目标部署图。本阶段只记录问题和改进方向，不改业务代码。

## 1. 总体评价

边界是清楚的。Collector 读夹具并做交叉验证，Agent 只消费已经采集的文本。获奖图片停在 `rights_blocked`。评委风格标签有 3 组门槛。同赛制比较拒绝跨组别混用。

主要缺口是运行时仍然是单进程内存模型。目标架构里的 PostgreSQL、队列和视觉模型没有落地，界面必须继续把「说明原句」和「看过像素」分开。

## 2. 问题

### P1-1 任务状态只存在当前进程

- 位置：`src/lib/tasks.ts`
- 现状：任务数组挂在 `globalThis.__pjiTaskStore`。创建研究任务后由 `setTimeout` 调用 `settleTask`。
- 影响：进程重启后，新建任务消失，种子任务恢复为启动时的副本。多实例之间也不会共享进度。
- 改进：持久化到以后的 `collection_tasks` / `agent_runs`。在那之前，界面继续说明这是进程内队列。
- 顺序：依赖数据库决策，不阻塞当前 POC。

### P1-2 文本证据可能被读成视觉结论

- 位置：`agents/text-evidence.ts`，作品页和报告页的「视觉分析 / 审美趋势」标题
- 现状：非空维度都附有原句，`pixelsRead` 固定为 false，报告有「像素趋势：未生成」。词表之外的句子不会生成维度。
- 影响：标题仍使用「视觉分析」「审美趋势」。读者可能把说明摘录当成模型看图的结果。
- 改进：保持原句和空维度。若以后接入视觉模型，用另一个模型名和 `pixels_read = true`，不要复用 `pji-text-evidence` 的记录。
- 顺序：文案可以再收紧；真正的像素分析要等授权图片和模型配置。

### P2-1 目标数据层没有运行

- 位置：`database/schema.sql`，`README.md` 的「什么是真的，什么是桩」
- 现状：表结构包含赛事、分析证据、来源观察和任务。应用不连接数据库，也没有迁移命令。
- 影响：不能用数据库约束复核唯一键；重启不保留任务。
- 改进：POC 继续以种子和测试为约束。生产化时再把 `qualityReport()` 的检查做成迁移后的查询。
- 顺序：在引入 PostgreSQL 时做，不提前写一套不会执行的 ORM。

### P2-2 来源没有原文哈希

- 位置：`src/lib/data/sources.ts`，provenance 组件
- 现状：`contentHash` 与 `rawContentSnapshot` 为空。界面写「未保存原文哈希」。
- 影响：官网改稿后无法自动发现种子过期。
- 改进：只有在允许保存原文、并且采集器真的发起请求时才计算哈希。
- 顺序：排在实时采集之后。

### P2-3 说明词表是封闭列表

- 位置：`agents/text-evidence.ts` 的 `SINGLE_RULES` 与 `SERIES_RULES`
- 现状：例如「消防员运送作品」只有短语 `firefighters transporting art` 命中才填写。系列分析不读取评委引语，也不把画幅人物小传改成视觉结论。
- 影响：新的获奖说明如果换了说法，维度会留空。这是故意的，但新增作品时要同步词表和测试。
- 改进：加作品时先补测试，证明 quote 是说明原文的子串，再增加短语。
- 顺序：随数据更新进行。

### P2-4 研究关系是长列表

- 位置：`src/lib/jury-graph.ts`，`src/components/jury-graph.tsx`
- 现状：Bindi Vora 的每条风格证据都是一条边。页面不画投票边，并写明匿名评审。
- 影响：关系完整，但滚动很长，不容易一眼看完缺口。
- 改进：按关系类型折叠。不要为了变短而删掉证据边。
- 顺序：可独立做，不改变数据规则。

### P3-1 任务页持续轮询

- 位置：`src/components/task-board.tsx`，`src/components/task-detail.tsx`
- 现状：每 1.2 秒请求一次任务列表，结束后也不停止。
- 影响：开发时无妨，页面久开会持续打 API。
- 改进：状态变为完成、失败或阻塞后停止轮询，重试时再开始。
- 顺序：小改动，可跟下一次任务界面调整一起做。

## 3. 风险

| 风险 | 现在怎么挡住 |
| --- | --- |
| 原图被托管或外链 | `imageAssets` 全部 `rights_blocked`，页面用占位 |
| 跨赛制比较 | `assertComparable` 与 `compareEditions` 只配对同一 `categoryId` |
| 评委投票被写成事实 | 研究图 `absent` 声明没有选择边；引语带 boundary |
| 样本不足仍写偏好 | 少于 3 组时风格字段为空，测试覆盖 Bindi、Paul 与零组样本 |
| 用户照片进入获奖库 | 上传分析不接收二进制，结果 `stored: false` |

## 4. 改进路线

1. 维持现有诚实性测试，作为以后接数据库和模型时的回归。
2. 任务持久化与原文哈希放到真正的采集进程里，不在本 POC 里模拟一次「已经抓过官网」。
3. 视觉模型单独建分析记录，不覆盖文本证据。
4. 研究关系列表可以折叠，但不减少证据。

## 5. 建议优先处理

没有需要立刻改业务代码的 P0。下一次产品改动优先保持 P1-2：任何新的分析文案都要能区分原句摘录和像素结论。P1-1 等到有数据库再做。

## 6. 本阶段未修改

未改业务代码、配置或数据库脚本。本文件是审查记录。
